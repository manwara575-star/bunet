# Improved Enterprise Video Security Plan - Recommended Enhancements

Your current plan is already strong because it correctly chooses **Bunny Embed-only playback**, avoids exposing raw `.m3u8/.ts/.mp4` URLs, uses **MediaCage Basic DRM**, adds signed embed URLs, and treats screen recording as a deterrence/tracing problem rather than a fully preventable browser problem. `PLAN.md` Bunny’s own docs support this direction: MediaCage Basic is designed to prevent third-party downloading by dynamically encrypting content and allowing it to load through the embed player, while embed token authentication secures iframe playback. ([Bunny.net Documentation](https://docs.bunny.net/stream/security-options?utm_source=chatgpt.com))

## 1. Add a Clear Security Guarantee Matrix

The plan should explicitly separate what the system **can block**, **can deter**, and **cannot technically guarantee**.

| Threat | Current Plan | Improvement |
|---|---|---|
| CocoCut/HLS segment download | Strong | Keep MediaCage Basic + Embed-only + no raw URL exposure |
| Copied iframe URL replay | Strong | Add `sessionId`, short TTL, revocation, heartbeat validation |
| Direct CDN path access | Strong | Use Advanced Token Auth only when direct paths are unavoidable |
| Browser devtools inspection | Moderate | Add CI tests proving no raw video URLs appear in HTML, JSON, logs, or analytics |
| Screen recording | Deterrence only | State clearly: watermarking + telemetry, not full prevention |
| Credential/key leakage | Needs more detail | Add secret rotation, key versioning, vault storage, audit logging |
| Insider/admin misuse | Needs more detail | Add RBAC, maker-checker approvals, admin audit logs |
| Webhook spoofing/replay | Needs more detail | Add webhook authentication, idempotency, replay protection |

This matters because Bunny’s advanced CDN token authentication supports HMAC-SHA256, directory tokens, optional IP validation, geo restrictions, and query control, but those controls do not solve browser or OS-level screen recording. ([Bunny.net Documentation](https://docs.bunny.net/cdn/security/token-authentication/advanced?utm_source=chatgpt.com))

## 2. Introduce Video Sensitivity Tiers

Add three protection levels so the system does not apply the same controls to every video.

### Tier A - Standard Course Videos

Use this for normal paid course content.

- Bunny Embed-only playback
- MediaCage Basic DRM
- Embed View Token Authentication
- Allowed domains
- Moving visible watermark
- Normal heartbeat
- 1-2 active device/session limit

### Tier B - Premium / High-Value Videos

Use this for expensive, exam, medical, confidential, or institution-owned content.

- Everything in Tier A
- Shorter embed TTL
- Stronger session binding
- More frequent heartbeat
- Risk scoring
- Automatic session revocation on suspicious behavior
- Mandatory visible watermark with user ID, timestamp, session ID, and course ID

### Tier C - Critical / Legal / Highly Confidential Videos

Use this only for very sensitive content.

- Everything in Tier B
- Manual approval before publishing
- Limited device policy
- Strong admin audit
- Optional upgrade path to Bunny MediaCage Enterprise DRM / platform DRM
- Separate Bunny library or pull zone
- Separate signing keys

## 9. Add Stronger Frontend Security Headers

The plan mentions CSP and Permissions-Policy, but the exact policy should be defined.

### Recommended baseline

```http
Content-Security-Policy:
  default-src 'self';
  script-src 'self';
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  connect-src 'self' https://video.bunnycdn.com https://*.b-cdn.net;
  frame-src https://iframe.mediadelivery.net https://*.bunnycdn.com;
  frame-ancestors 'self';
  media-src 'none';
  object-src 'none';
  base-uri 'self';
  form-action 'self';

Permissions-Policy:
  display-capture=(),
  picture-in-picture=(),
  camera=(),
  microphone=(),
  geolocation=()

Referrer-Policy:
  strict-origin-when-cross-origin

X-Content-Type-Options:
  nosniff
```

`display-capture=()` can stop the document itself from initiating screen capture through `getDisplayMedia()`, but it cannot stop external OS-level recording tools. MDN documents that `display-capture` controls whether the document can use the Screen Capture API. ([MDN Web Docs](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Permissions-Policy/display-capture?utm_source=chatgpt.com)) CSP `frame-src` controls where your page may load iframes from, while `frame-ancestors` controls who may embed your page, so both should be configured intentionally. ([MDN Web Docs](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-src?utm_source=chatgpt.com))

## 16. Improve Bunny Encoding Configuration Section
